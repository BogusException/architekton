Purpose

data_loader.py reads a CSV or JSON file from disk and returns a list of record dicts. It is the first stage of the pipeline. The module docstring says it validates required columns and raises ValueError with a readable message on failure.

Key functions

- load_csv(path) (lines 15-26): opens the file with newline="", reads it with csv.DictReader, compares the header set to REQUIRED_COLUMNS ({id, name, value, timestamp}, line 12), raises ValueError with the sorted missing names, otherwise returns a list of row dicts.
- load_json(path) (lines 29-35): parses the file with json.load and raises ValueError if the top-level value is not a list. Returns the list as is.
- load(path) (lines 38-45): picks load_csv or load_json from the file suffix (Path.suffix) and raises ValueError("Unsupported file type: ...") for anything else.

Design choices

- Standard library only (csv, json, pathlib). No dependencies.
- Dispatch is by file extension, not by content sniffing. This is simple and predictable.
- Errors are ValueError with a message meant for the user, which cli.py prints directly.
- The required-column check runs before any row is read, so a wrong file fails fast.
- dict(row) copies each row into a plain dict, so callers do not depend on DictReader internals.
- Required columns are a module-level set, easy to change or test.

Risks and missing error handling

1. Docstring mismatch (lines 3-4). The module says it validates required columns, but only load_csv does. load_json performs no column check and does not check that list items are dicts. A JSON file such as [1, 2, 3] or [{"x": 1}] loads without error and fails later in the transformer (TypeError or AttributeError) or in validation.
2. All CSV values are strings. "value" is never converted here. Later stages must handle that.
3. Encoding is not set in either open() call (lines 18 and 31). The platform default is used, so the same file can behave differently on different machines. A UTF-8 BOM at the start of a CSV makes the first header read as "﻿id", and the file is rejected with "missing required columns: ['id']". Opening with encoding="utf-8-sig" would fix this.
4. Suffix check is case-sensitive (lines 41, 43). "DATA.CSV" and "data.JSON" give "Unsupported file type". A file with no suffix gives the message "Unsupported file type: " with nothing after the colon.
5. Ragged CSV rows are not detected. A short row gets None for missing fields. A long row puts extra cells in a list under the key None (DictReader restkey default). Neither raises an error.
6. An empty CSV has fieldnames None, so every column is reported missing. A CSV with only a header row returns [] with no warning.
7. Duplicate header names are collapsed by DictReader (the last column wins) and the set() on line 20 hides the duplication.
8. The whole file is read into memory. Large inputs have no streaming option.
9. OSError cases other than FileNotFoundError (PermissionError, IsADirectoryError) are not translated into a friendly message. Malformed JSON raises json.JSONDecodeError, which is a ValueError but has a parser-style message without the file name.
10. load_csv and load_json take str, but load() wraps the path in Path only for the suffix check. A Path argument works at runtime, but the type hints say str.
