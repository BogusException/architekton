M03 PERFORMANCE BOTTLENECKS: validator.py (93 lines)

Method: static read of the source, plus a timing run on 100,000 transformed
records (3 default rules, best of 3, CPython). Multipliers marked "measured"
come from that run. The others are estimates.
N+1 patterns: none (no lookups against external data). I/O: none.

Baseline: validate(100k records, 3 rules) = 0.087 s.

------------------------------------------------------------------
1. Per-record, per-rule indirect call with dict lookup  [HIGH]
------------------------------------------------------------------
Location: validate(), lines 75-80.

    for record in records:
        failures = []
        for rule_name in active_rules:
            msg = _RULES[rule_name](record)

For N records and R rules this runs N*R global-dict lookups (_RULES[...]),
N*R Python function calls, and N*R repeats of record.get() on the same
record. The rule names are the same for every record, so the lookup is
wasted work after the first record.

Fix: resolve the rule functions once, before the loop.

    checks = [(name, _RULES[name]) for name in active_rules]
    for record in records:
        failures = [f"{name}: {msg}"
                    for name, fn in checks
                    if (msg := fn(record))]

This removes N*R dict lookups and replaces the inner append loop with a
comprehension (fewer bytecode steps per rule).

Estimated improvement: 1.1x to 1.2x.

Further step (changes the design, so only with a yes): fuse the three
built-in rules into one function that reads each field once. A hand-inlined
version of the three rules with the same output was timed at 0.044 s.

Measured: 0.044 s vs 0.087 s = 2.0x faster. The cost is that custom rules
registered through @rule would not benefit, and the registry becomes less
useful.

------------------------------------------------------------------
2. Failure strings built eagerly for every failure  [MEDIUM]
------------------------------------------------------------------
Location: line 80 and the rule bodies (lines 27, 35, 37, 44).

Each failure builds a prefixed f-string ("rule_name: msg"), and the rule
itself often builds another f-string with repr() of the value (line 37).
On a dirty file where most records fail, this is the dominant cost. On a
clean file it never runs.

Fix: have rules return a short code or a (name, value) tuple, and format the
text only in reporter.py when output is rendered. The reporter already
skips passing records in text mode.

Estimated improvement: 1.3x on inputs with a high failure rate (over 20%).
No change on clean input.

------------------------------------------------------------------
3. Second numeric parse of "value"  [MEDIUM]
------------------------------------------------------------------
Location: value_non_negative(), line 34.

float(record.get("value", 0)) runs again for every record, even though the
default pipeline has already normalized "value" to float in
transformer.normalize_value. Python's float() on an existing float is cheap
but still a call. When the validator runs on non-normalized data, the cost
is a real string parse.

Fix: skip the cast when isinstance(v, float).

    v = record.get("value", 0)
    if not isinstance(v, float):
        v = float(v)

Estimated improvement: 1.1x on this rule, under 1.05x overall.

------------------------------------------------------------------
4. Intermediate results list plus a second pass to count  [LOW]
------------------------------------------------------------------
Location: lines 74 and 87.

    passed = sum(1 for r in results if r.passed)

This walks the full results list again after the main loop. A counter
incremented in the loop avoids it. Also, RecordResult objects are built for
passing records that the text reporter never prints.

Measured: the extra pass is about 4 ms per 100k records (about 5% of
total).

Fix: count in the loop (passed += not failures).

Estimated improvement: 1.05x.

Memory: RecordResult is a regular dataclass with __dict__. Using
@dataclass(slots=True) (Python 3.10+) cuts per-record memory by about 40%
and speeds attribute access slightly. Estimated 1.05x speed, 1.6x less
memory for results.

------------------------------------------------------------------
5. str() call and strip() allocation in name_not_empty  [LOW]
------------------------------------------------------------------
Location: line 43.

str(record.get("name", "")).strip() allocates a stripped copy just to test
truthiness. For str inputs str() is a no-op call. For None it produces
"None", which passes (a correctness bug, not a speed issue).

Fix: test without allocating.

    name = record.get("name")
    if not isinstance(name, str) or name.isspace() or not name:

Estimated improvement: 1.1x on this rule. Under 1.03x overall.
