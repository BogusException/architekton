7. validate (lines 67-93)
----------------------------------------------------------------------------------------------
Time: O(n * k) (plus O(k) setup). Space: O(k) auxiliary; output O(n * (1 + f)) where f is the
number of failure strings per record, f <= k, so output is O(n * k) worst case.
Reasoning, by line:
  - Line 69: rules or list(_RULES). Copies the registry keys, O(k).
  - Line 70: the comprehension runs once per active rule. The test r not in _RULES is on a
    dict (hash lookup, O(1) average), not on a list, so the total is O(k). No quadratic
    membership test. The temporary list unknown holds at most k names, O(k) space.
  - Lines 71-72: O(1) test. On failure the error string is O(k), raised once.
  - Line 74: results = [] grows by exactly one RecordResult per record, so O(n) elements.
  - Line 75: outer loop over records, n iterations.
  - Line 76: a fresh failures list per record, O(1) to create.
  - Line 77: inner loop over active_rules, k iterations. This is the only nested loop. It is a
    loop over rules, not a second loop over records, so it is O(n * k) and not O(n^2).
  - Line 78: _RULES[rule_name] is a dict lookup, O(1). The rule call is O(1) per sections 3-5
    (O(L) for value_non_negative and name_not_empty, bounded). No regex is used anywhere in
    the file, so there is no compilation inside a loop.
  - Lines 79-80: one f-string append per failing rule. Append is amortized O(1). The string
    is O(L) because it embeds the rule message.
  - Lines 81-85: one RecordResult per record. str(record.get("id", "(no id)")) is O(L).
    The failures list is stored by reference, not copied.
  - There is no uniqueness or duplicate check across records. No record is compared with any
    other record, so nothing is quadratic in n.
  - Line 87: the generator sum over results is O(n), one pass.
  - Lines 88-93: constructing the report is O(1). len(results) is O(1).
  Total time: O(k) + O(n * k) + O(n) = O(n * k).
  Space accounting:
    Auxiliary: active_rules and unknown are O(k). Loop locals (failures, msg, record) are O(1)
    beyond what is retained in the output.
    Output: results holds n RecordResult objects, each with a failures list of up to k
    strings. That is O(n) when most records pass and O(n * k) when most records fail every
    rule. This space is required by the return value.
k case: k is bounded by the registry size (3 built-in rules, a small constant) because
unknown names are rejected on lines 70-72. k does not grow with n. The one way k can exceed
the registry size is a caller passing duplicate names (for example ["has_id"] * 1000). That
input is chosen by the caller, not derived from n, so the case that applies is "k independent
of n" and O(n * k) is not flagged. If a future caller sets k proportional to n, the cost would
become O(n^2), and a dedupe on line 69 (see below) would cap k at the registry size.
FLAG: none

Optional hardening (not required, no flag): dedupe repeated rule names so k cannot exceed
the registry size.
    active_rules = list(dict.fromkeys(rules)) if rules else list(_RULES)
This keeps the order, runs in O(k), and bounds the inner loop at the registry size.
