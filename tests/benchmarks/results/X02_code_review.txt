X02 code review: tests/benchmarks/sample_jobs/small_project/

=== cli.py ===
Does well:
- Each pipeline stage is one call (lines 54-57), so the flow reads top to bottom and each stage can be tested alone.
- Input errors and validation failures use different exit codes: line 58 exits 1 when report.ok is False, line 61 exits 2 for ValueError or FileNotFoundError.
- Defaults live in module constants (lines 16-17) and the help strings reuse them, so documented defaults match real ones.
Could break:
- main, line 59: a file without read permission raises PermissionError, and a directory passed as the file raises IsADirectoryError. Neither is caught, so Python prints a traceback and exits 1, the same code as a validation failure.
- main, lines 26-28: `cli.py --steps strip_whitespace data.csv` makes argparse consume data.csv as a step (nargs="*"), so the positional file is missing and argparse exits 2 with a usage error.
- main, lines 27 and 55: `--steps` with no values gives [] and the transform stage is skipped silently.
- Lines 10-13 use bare imports, so the script only runs when its own directory is on sys.path (for example `python cli.py`, not `python -m small_project.cli`).
Improvement:
- Change line 59 to `except (OSError, ValueError) as err:` so every file error prints a clean message and exits 2.

=== data_loader.py ===
Does well:
- load_csv checks the header against REQUIRED_COLUMNS (lines 20-23) before it reads any row, and the error lists the missing names sorted.
- load_csv opens with newline="" (line 18), so quoted fields with embedded newlines parse correctly.
- load (lines 38-45) keeps the format choice in one place and raises ValueError for unknown suffixes.
Could break:
- load_csv, line 18: open() has no encoding. A UTF-8 file with a BOM makes the first header start with an invisible BOM character, so the file is rejected as missing "id" although it looks correct.
- load_json, lines 33-34: only the container type is checked. `[1, 2]` or `[null]` passes, and later stages crash with AttributeError in strip_whitespace (transformer.py line 36) or in validate. The CSV path enforces columns, the JSON path does not.
- load, lines 41-43: `p.suffix` is case-sensitive, so DATA.CSV is rejected as unsupported.
- load_csv, lines 24-25: a short row gives None for missing columns, and a long row stores extras under the key None. Neither is detected.
Improvement:
- In load_json, require every item to be a dict and apply the same REQUIRED_COLUMNS check, preferably through one shared helper used by both loaders.

=== reporter.py ===
Does well:
- _text_lines builds a list and to_text joins it, so text output is easy to test without capturing stdout.
- to_json uses an explicit key mapping, so the JSON schema is stable even if ValidationReport gains fields.
- write has one exit point for both formats and both destinations.
Could break:
- write, line 57: Path.write_text has no encoding and adds no trailing newline, while the stdout branch (print) adds one. File and stdout output differ by one byte.
- write, line 57: a missing parent directory raises FileNotFoundError (caught by cli.py), but a read-only target raises PermissionError, which is not caught and gives a traceback.
- write, line 55: an unknown fmt such as "xml" silently falls back to text. cli.py restricts the choices, but any other caller gets no error.
- The text report lists every failing record. A large file with many failures prints an unbounded report.
Improvement:
- Validate fmt (raise ValueError for unknown values) and write with encoding="utf-8" and a trailing newline so file and stdout output match.

=== transformer.py ===
Does well:
- The @register decorator keeps the step list in one place. A new step is one decorated function, and apply needs no change.
- Every transform copies the record (dict(record) or a new dict comprehension), so input records are never mutated.
- apply checks all step names before it touches any data (lines 49-51), so a typo fails fast and not halfway through.
Could break:
- add_flag, line 43: float(out.get("value", 0)) has no try/except, unlike normalize_value. Without normalize_value first, value "" or "abc" raises ValueError, and value None (JSON null) raises TypeError. TypeError is not caught by cli.py, so the user sees a traceback.
- add_flag with value "nan": float("nan") > 100 is False, so NaN is never flagged. normalize_value also passes NaN through, and value_non_negative then passes it (nan < 0 is False).
- strip_whitespace, line 36: record.items() fails with AttributeError when a record is not a dict (see data_loader.load_json).
- Step order matters but is not documented or checked. `--steps add_flag normalize_value` behaves differently from the default order.
Improvement:
- Make add_flag reuse the same safe float conversion as normalize_value (one private helper), so the two steps handle bad values the same way.

=== validator.py ===
Does well:
- Rules are small functions that return None or a message, so each one is trivial to unit test.
- validate checks rule names up front (lines 70-72) and prefixes each failure with the rule name, so the report shows which rule failed.
- ValidationReport.ok is derived from failed, so the flag cannot disagree with the counts.
Could break:
- validate, line 69: `rules or list(_RULES)` treats an empty list as "all rules". `--rules` with no values runs every rule, while `--steps` with no values runs none. The two flags behave in opposite ways.
- has_id, line 26: `not record.get("id")` rejects the integer 0 and any other falsy id. A JSON file with "id": 0 fails with "missing or empty".
- validate, line 82: a non-dict record raises AttributeError on record.get. Records from load_json are not guaranteed to be dicts.
- Duplicate ids are not detected, and record_id is a plain str, so two records with the same id give ambiguous failure lines in the report.
- An empty input list gives total=0, failed=0, ok=True, so an empty file reports PASSED.
Improvement:
- Use `rules if rules is not None else list(_RULES)` and change has_id to test `record.get("id") in (None, "")`, so an explicit empty list and an id of 0 are both handled correctly.
