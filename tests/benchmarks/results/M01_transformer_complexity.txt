2. normalize_value (lines 23-30)
----------------------------------------------------------------------------------------------
(1) Name and range: normalize_value, lines 23-30.
(2) Time: O(m + s) per record.
(3) Space: O(1) auxiliary. Output: O(m) for the new dict (the output is the shallow copy).
(4) Reasoning:

  - Line 27: out.get("value", 0) is an O(1) dict lookup. float() on a string parses it in O(s).

  - Lines 28-29: the except path sets 0.0 in O(1). A failed float() parse costs at most O(s).
  - No loop over fields, no list membership test, no sort, no grouping.
  - Total per record: O(m) copy + O(s) parse. Over n records in one pass: O(n(m + s)).

FLAG: none

3. strip_whitespace (lines 34-36)
----------------------------------------------------------------------------------------------
(1) Name and range: strip_whitespace, lines 34-36.
(2) Time: O(m * s) per record in the worst case.
(3) Space: O(1) auxiliary. Output: O(m) for the new dict, plus up to O(m * s) for the new strings.
(4) Reasoning:
  - Line 36 is a dict comprehension that visits each of the m items once: O(m) iterations.
  - For each item, isinstance is O(1). For a str value, v.strip() scans both ends and builds a
    new string when whitespace is present: O(s) time and O(s) space for that string. CPython
    returns the same object when there is nothing to strip, but the scan itself is still O(s)
    in the worst case (a string made of whitespace).
  - Non-string values are passed through by reference in O(1).
  - Total per record: m fields times O(s) = O(m * s). Over n records in one pass: O(n * m * s).
  - Linear in n. This is the most expensive of the three built-in steps, and the only one whose
    output may hold new strings.
(5) Flag:
FLAG: none
(6) Alternative: not needed.

5. apply (lines 47-55)
----------------------------------------------------------------------------------------------
(1) Name and range: apply, lines 47-55.
(2) Time: O(k * n * m * s) worst case (every step is strip_whitespace; step names may repeat).
    If only the cheap steps run, it is O(k + n * k * (m + s)).
    In general: O(k + sum over steps of n * cost(step)), with cost(step) from sections 2 to 4.
    The result is linear in n and linear in k.
(3) Space: auxiliary O(n + k), with a transient peak of O(n * m) (see below). Output: O(n * m)
    for n new dicts, plus up to O(n * m * s) if strip_whitespace created new strings.
(4) Reasoning:
  - Line 49: a list comprehension over the k step names. Each test "s not in _REGISTRY" is a
    dict membership test, O(1) on average. The membership test is against the dict, not a list,
    so there is no O(k * R) scan. Time O(k), space O(k) for the unknown list in the worst case.
  - Lines 50-51: raise on unknown names. O(k) to format the message.
  - Line 52: list(records) copies the outer list only. Time O(n), space O(n). Record dicts are
    shared with the caller until the first step replaces them.
  - Line 53: loop over k steps.
  - Line 54: for each step, a list comprehension over n records. Each iteration does one O(1)
    dict lookup _REGISTRY[step] and one call to the transformation. Each call builds a fresh
    dict of m pairs (sections 2 to 4), so one pass costs O(n * m) for copying plus the parse or
    strip cost: O(n * m * s) for strip_whitespace, O(n * (m + s)) for the other two.
  - The k passes are sequential, not nested over n. There is no pass that compares records to
    each other, so the cost never becomes quadratic in n.
  - Memory: the old list and the new list are both alive while a comprehension runs, so the
    transient peak is about two generations of n dicts, which is O(n * m). The previous
    generation is freed when result is rebound on line 54. For k = 0 the output is only the
    O(n) list copy.
  - No sorting, no deduplication, no grouping, no string building over all records.
  - Cost of calls into other modules: none. No sibling module is imported.
(5) Flag:
FLAG: none
(6) Alternative: not needed for complexity. Optional constant-factor note, not a flag: each step
    makes a full dict copy per record, so k steps make k copies per record (O(k * n * m) in
    copy work alone). Fusing the steps into one per-record loop would copy once:
        out = dict(r)
        for fn in fns: out = fn(out)   # fns would need to mutate in place
    This would cut copy work from O(k * n * m) to O(n * m), but it changes the documented
    contract that each transformation returns a copy, so it is not recommended without a test
    change.
